# x86_64 の glibc 用プログラムのサンプルと、速さの比べ方

## bench4 (Box64・QEMU・ネイティブの速さを比べる)

`bench4.c` は、1 つのプログラムで次の 3 種類を測るベンチマーク。`bench.sh` が、これに
「4. 起動の速さ」を加えた 4 項目を、ネイティブ (arm64)・Box64・QEMU で測って表で出す。

| 項目 | 中身 |
|---|---|
| 1. 整数の計算とループ | xorshift 乱数の足し合わせ・掛け算・ビット演算 (割り算なし) |
| 2. メモリの読み書き | エラトステネスのふるい (1200 万まで)、大きな配列のコピーと読み出し |
| 3. libc の関数 | memcpy・snprintf・strcmp・qsort・sin/cos |
| 4. 起動の速さ | 何もしないで終わる (`bench4 noop`) を 50 回起動する時間 |

各項目の結果の値 (チェックサム) も出すので、どの方法でも同じ計算をしたか確かめられる
(PC での確認: gcc の x86_64 版と、端末の tcc で作る arm64 版で同じ値になった)。

### いちばん簡単な測り方

アプリの 設定 → 個人設定 →「速度を比べる (ネイティブ・Box64・QEMU)」。何も準備しなくてよい
(サンプルは APK に入っている)。結果は次のような表になる:

```
結果 (秒。小さいほど速い)
ネイティブ     Box64      QEMU Box64速さ  項目
   0.141s    0.052s    0.520s    10.0倍  1. 整数の計算とループ (割り算なし)
   ...
```

「Box64速さ」は Box64 が QEMU の何倍速いか。Box64 が使えない端末では、その理由が下に出る。

### コマンドプロンプトで測る

1. `bench4-x86_64` を「プログラムを追加」で登録する (登録名は `bench4-x86_64.Gelf`)
2. `bash bench.sh bench4-x86_64.Gelf 1` (2 つ目の数は計算の量。遅い端末なら 0.5 など)

x86_64 版は起動スクリプトの環境変数 `BR_X86` (`box64` / `qemu`) で、その 1 回だけ実行方法を選んで動かす。
ネイティブ版は同じソースを mkexe (端末の tcc) で arm64 の bionic 向けにビルドして、`/system/bin/linker64`
に読み込ませて動かす (初回は mkexe がヘッダなどを約 2MB 取ってくる)。tcc は gcc ほど最適化しないので、
ネイティブ版は「本来のネイティブ」より遅めに出る (x86_64 版は gcc -O2)。

### ビルドのしかた

x86_64 の Linux の PC で (glibc 2.44 より新しい環境ではビルドしないこと):

```sh
gcc -O2 -o bench4-x86_64 bench4.c -lm
```

同梱の `bench4-x86_64` は Ubuntu 24.04 (glibc 2.39) の gcc でビルドしたもの (必要な glibc は 2.34 まで)。
APK には、ビルドのときに `app/build.gradle` の `copyBenchAssets` が `bench4.c`・`bench4-x86_64`・`bench.sh`
を `assets/bench/` に写して入れる。

## primes (素数を数える)

`primes-x86_64` は、指定した数までの素数を数える小さなサンプル (割り算ばかりなので、Box64 と QEMU の差は
出にくい)。登録して `primes-x86_64.Gelf 3000000` → `3000000 までの素数: 216816 個`。
ビルドは `gcc -O2 -o primes-x86_64 primes.c`。
