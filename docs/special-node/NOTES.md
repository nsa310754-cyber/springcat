## 確実に言えること
- ノードは **1〜29 の番号付き**（手描きで全 29 ノード前後）。
- **ノード1 が入口（根）**。図の右端にあり、そこから左へツリー状に広がる。
  - コード上の解禁フラグは `_specialNodeUnlocked`（`localStorage: blockdestory_specialNodeUnlocked`）。
    パック購入 (`pack_starskip`) でこのフラグが立つ。
- ノード1 → ノード2 の一本道で始まり、**ノード2 が最初の分岐点**（上枝・下枝へ二又）。
- そこから左へ行くほど枝分かれし、左端が末端ノード
  （読み取れる範囲で 22 / 25 / 29 / 23 / 24 / 18 / 28 / 26 などが葉）。
- 上部に 22–21–20 の一本鎖があり、20 が中央の 12 付近へ合流する。

## アンロック順（実装済み ✅）
> 方式: **「木の1段下(rootに近い)で繋がっている隣接ノードをすべて取得」すると上のノードが解禁**。
> 合流点は複数の前提が必要。横並びだけのノードは同段の隣が前提。
> `SPECIAL_NODE_EDGES` と row から自動生成（`SPECIAL_NODE_PREREQ`）するので配線と常に一致。

前提(← が必要ノード):
```
1←起点     2←1      3←2      4←2      5←4      6←4      7←3
8←5       9←6,7    10←5     11←7     12←10    13←11    14←9
15←14     16←14    17←13,15 18←17    19←15    20←12    21←20
22←21     23←19    24←17    25←24    26←16    27←12    28←27   29←27
```
- 合流(2つ必要): **9 ← 6・7** / **17 ← 13・15**（画像で枝が2本合流している点）。
- 到達性チェック: 全29ノードが 1 から順(1→2→…→29)に解禁可能 ✅。
- 進行シミュレーション(貪欲・最安から購入): **582回claim ≈ 72日**で全取得。
  ノード18(cost 400)は64回目で取得、以降はSSP控除なし（所持要件は残るためノード29は
  1e6=上限を実際に貯める必要あり）。

## 実装メモ
- 描画: `renderSpecialNodeModal` → `ensureSpecialNodeTree` → `_snBuildTreeSvg`（SVGで枝+丸）。
  色: 緑=取得済 / 紫(発光)=取得可能 / 灰=前提ロック / 濃紫=SSP不足。タップで詳細+取得ボタン。
- 購入判定: `_snStatus` / `_snMissingPrereqs`（前提）＋ `buySpecialNode` で二重チェック。
- 保存: `blockdestory_specialNodePurchased = {1:true,...}`（`_extraKeys` 登録済で引き継ぎ対応）。
