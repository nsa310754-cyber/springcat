# ScreenLink

許可された端末同士だけで、画面を見せ合うための社内向けリモートサポートツールです。
「見るだけ(view-only)」に機能を絞っています。リモートからの操作・コマンド実行・ファイルアクセスは実装していません。

構成:

- `server/` — 中継(ペアリング)サーバー。Node.js + WebSocket。
- `deploy/` — サーバーを実際に立てるための一式(Docker Compose + Caddy自動TLS、systemdユニット)。
- `android/` — Android アプリ(ScreenLink)。ホスト(画面を見せる側)にもビューア(見る側)にもなれます。
- `dist/ScreenLink-1.0-debug.apk` — ビルド済みAPK(社内配布・検証用のdebug署名)。

## セキュリティモデル

1. **端末は事前登録制**: `server/devices.json` に管理者が端末ID・シークレット・グループを
   登録した端末しか、そもそもサーバーに接続できません(不明な端末は`hello`の時点で拒否)。
2. **同じグループ内でしか見えない**: 端末は自分と同じ `group` の端末しかロスター(一覧)に
   表示されず、view要求もグループ内でしか成立しません。
3. **1対1の中継のみ**: サーバーはブロードキャストせず、承認済みセッションの2端末間だけに
   フレームを中継します。フレーム内容の保存・ログ出力はしません。
4. **画面共有には必ず本人操作が要る**: 誰かが「見たい」とリクエストしても、ホスト端末側で
   ユーザーが「許可」を押し、さらにAndroid標準のスクリーンキャプチャ同意ダイアログを
   承認しない限り、共有は始まりません。この同意ダイアログはOS側の仕組みなので
   アプリからスキップできません。
5. **共有中は常時通知が出る**: 画面共有中はAndroidの仕様上、常駐通知を消せません
   (「共有を停止」ボタン付き)。ホスト端末の利用者は共有中であることに必ず気づけます。
6. **リモート操作機能はなし**: 入力送信・コマンド実行・ファイル転送のメッセージ種別は
   プロトコルに存在しません。画面フレームの片方向中継のみです。

## サーバーを立てる

### 方法A: Docker + 自動TLS(インターネット越しに使う場合。推奨)

VPSや自宅サーバーなど、ドメインをそのIPに向けられるマシンで実行します。
`deploy/` が「サーバーを立てる装置」一式です — 中継サーバーと、TLS証明書を
自動取得するCaddyのリバースプロキシをまとめて起動します。

```bash
cd deploy
cp .env.example .env
# .env を編集し、このホストを指すDNS名を DOMAIN= に設定
./setup.sh
```

`setup.sh` は Docker Compose でビルド・起動し、`wss://<DOMAIN>` で待ち受けます
(Let's Encrypt証明書はCaddyが自動取得)。生の中継サーバー(8787番)はホストに
公開されず、Caddy経由でしかアクセスできません。

端末の登録・一覧・削除:

```bash
docker compose exec relay node manage-devices.js add "表示名" <group>
docker compose exec relay node manage-devices.js list
docker compose exec relay node manage-devices.js remove <deviceId>
```

登録・削除後は再起動せずに反映できます:

```bash
docker compose kill -s HUP relay
```

### 方法B: systemd(社内LANのみで使う場合)

ドメインを取得せず、社内LAN内の端末同士だけで使うなら `deploy/systemd/` の
手順でホストに直接インストールできます(手順はユニットファイル冒頭のコメント参照)。
この場合は平文 `ws://` になるため、信頼できるネットワーク内でのみ使ってください。
インターネットに公開する場合は必ず方法Aか、自前のリバースプロキシでTLS終端してください。

### 手動セットアップ(Dockerを使わない場合)

```bash
cd server
npm install
node manage-devices.js add "表示名" <group>   # devices.json が自動生成されます
PORT=8787 node server.js
```

同じ `group` を持つ端末同士だけがお互いを見つけられます(例: `"group": "office-fleet"`)。
この方法でインターネットに公開する場合も、必ずTLS(`wss://`)の背後に置いてください。

## Android アプリのセットアップ

各端末で ScreenLink アプリを開き、以下を入力して「登録して接続」:

- サーバーURL (`wss://your-server:8787` など)
- 端末ID・シークレット (管理者が `devices.json` に登録したもの)
- この端末の表示名

登録が終わると、同じグループの他端末が一覧に表示されます。一覧の端末をタップすると
その端末に「画面を見せてほしい」というリクエストが送られ、相手が許可すると閲覧が始まります。

### ビルド方法

```bash
cd android
./gradlew assembleDebug
# 生成物: app/build/outputs/apk/debug/app-debug.apk
```

Play ストア配布や社外配布を行う場合は、必ず自前のリリース用keystoreで署名し直してください
(このリポジトリにdebug署名のAPKは含まれていますが、リリース署名鍵は含まれていません)。

## スコープ外にしていること(意図的)

このツールは「許可した自社端末同士でリモートサポートのために画面を見る」という要件に
合わせて意図的に機能を絞っています。以下は実装していません:

- リモート操作(タップ・入力のリレー)
- 任意コマンド実行やシェルアクセス
- 位置情報・通話・SMS・連絡先などの収集
- 通知を隠す/同意ダイアログを回避する仕組み

これらが必要な場合は、要件と権限の範囲を明確にしたうえで別途検討してください。
