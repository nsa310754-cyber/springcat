# ScreenLink

許可された端末同士だけで、画面を見せ合うための社内向けリモートサポートツールです。
「見るだけ(view-only)」に機能を絞っています。リモートからの操作・コマンド実行・ファイルアクセスは実装していません。

**サーバーはAPKの中に組み込まれています。** 別途VPSやDockerを用意しなくても、
許可した端末のうち1台を「サーバーモード」にすれば、それだけで他の端末とつながります。

構成:

- `android/` — Android アプリ(ScreenLink)。1台を中継サーバーにでき、ホスト
  (画面を見せる側)にもビューア(見る側)にもなれます。
- `dist/ScreenLink-1.0-debug.apk` — ビルド済みAPK(社内配布・検証用のdebug署名)。
- `server/`, `deploy/` — 同じ中継プロトコルのNode.js実装。社外拠点をまたぐ、
  同じLANにいない端末同士をつなぎたい場合など、独立サーバーを別途立てたい人向けの
  代替手段(任意)。通常は不要です。

## 使い方(APK内蔵サーバーだけで完結)

1. **サーバー役を1台決める**: 常時電源が入っている端末(事務所に置きっぱなしの
   タブレット等)にアプリを入れ、「この端末をサーバーにする / サーバー管理」を開く。
2. その画面で「端末を追加」を押し、見せる/見る側になる端末の表示名とグループ名を入力。
   生成された **サーバーURL・端末ID・シークレット** が表示されるので、それぞれの端末の
   持ち主に伝える(画面を見せて入力してもらう、メモを渡す、など)。
3. 「稼働」トグルをONにするとサーバーが起動し、`ws://<このAndroid端末のIP>:8787` で
   待ち受ける。他の端末は同じWi-Fi/LANにいれば、このアドレスに接続できる。
4. 他の各端末でアプリを開き、「端末の登録」画面に手順2の値を入力して「登録して接続」。
5. 登録が終わると、同じグループの他端末が一覧に表示される。見たい端末をタップすると
   その端末に「画面を見せてほしい」というリクエストが送られ、相手が許可すると閲覧が始まる。

サーバー役の端末はホスト/ビューアも兼任できます(自分自身を宛先にした登録は不要で、
サーバー管理画面とは別に、通常の「端末の登録」で自分のグループの他端末を見にいけます)。

**注意**: APK内蔵サーバーは平文の `ws://` で待ち受けます。同じ拠点・同じ信頼できる
LAN/Wi-Fi内で使うことを想定しています。異なる拠点をまたいで使う場合や、信頼できない
ネットワーク経由で使う場合は、下記の独立サーバー(`server/`)をTLS付きで別途立ててください。

## セキュリティモデル

1. **端末は事前登録制**: サーバー役の端末で管理者が明示的に追加した端末しか、
   そもそも接続できません(不明な端末ID・シークレットは接続時点で拒否されます)。
2. **同じグループ内でしか見えない**: 端末は自分と同じ `group` の端末しかロスター(一覧)に
   表示されず、view要求もグループ内でしか成立しません。
3. **1対1の中継のみ**: サーバーはブロードキャストせず、承認済みセッションの2端末間だけに
   フレームを中継します。フレーム内容の保存・ログ出力はしません。
4. **画面共有には必ず本人操作が要る**: 誰かが「見たい」とリクエストしても、ホスト端末側で
   ユーザーが「許可」を押し、さらにAndroid標準のスクリーンキャプチャ同意ダイアログを
   承認しない限り、共有は始まりません。この同意ダイアログはOS側の仕組みなので
   アプリからスキップできません。
5. **共有中は常時通知が出る**: 画面共有中はAndroidの仕様上、常駐通知を消せません
   (「共有を停止」ボタン付き)。ホスト端末の利用者は共有中であることに必ず気づけます。
   サーバー稼働中であることも同様に常駐通知で示されます。
6. **リモート操作機能はなし**: 入力送信・コマンド実行・ファイル転送のメッセージ種別は
   プロトコルに存在しません。画面フレームの片方向中継のみです。

### ビルド方法

```bash
cd android
./gradlew assembleDebug
# 生成物: app/build/outputs/apk/debug/app-debug.apk
```

Play ストア配布や社外配布を行う場合は、必ず自前のリリース用keystoreで署名し直してください
(このリポジトリにdebug署名のAPKは含まれていますが、リリース署名鍵は含まれていません)。

## 独立サーバーを別途立てたい場合(任意・上級者向け)

同じLANにいない端末同士(拠点をまたぐ、外出先から等)をつなぎたい場合は、
APK内蔵サーバーの代わりに `server/` のNode.js実装をクラウド等に立てられます。
プロトコル・セキュリティモデルはAPK内蔵サーバーと同一です。

### Docker + 自動TLS(推奨)

```bash
cd deploy
cp .env.example .env
# .env を編集し、このホストを指すDNS名を DOMAIN= に設定
./setup.sh
```

`setup.sh` は Docker Compose でビルド・起動し、`wss://<DOMAIN>` で待ち受けます
(Let's Encrypt証明書はCaddyが自動取得)。生の中継サーバー(8787番)はホストに
公開されず、Caddy経由でしかアクセスできません。

```bash
docker compose exec relay node manage-devices.js add "表示名" <group>
docker compose exec relay node manage-devices.js list
docker compose exec relay node manage-devices.js remove <deviceId>
docker compose kill -s HUP relay   # 登録・削除後、再起動せず反映
```

### systemd / 手動セットアップ

`deploy/systemd/screenlink-relay.service` のコメントを参照(Dockerを使わない場合)。
この場合は平文 `ws://` になるため、信頼できるネットワーク内でのみ使うか、
自前のリバースプロキシでTLS終端してください。

```bash
cd server
npm install
node manage-devices.js add "表示名" <group>   # devices.json が自動生成される
PORT=8787 node server.js
```

独立サーバーを使う場合、Androidアプリ側の「サーバーURL」に `wss://your-server` を
入力するだけで、それ以外の手順(端末の登録・閲覧の流れ)はAPK内蔵サーバーと同じです。

## スコープ外にしていること(意図的)

このツールは「許可した自社端末同士でリモートサポートのために画面を見る」という要件に
合わせて意図的に機能を絞っています。以下は実装していません:

- リモート操作(タップ・入力のリレー)
- 任意コマンド実行やシェルアクセス
- 位置情報・通話・SMS・連絡先などの収集
- 通知を隠す/同意ダイアログを回避する仕組み

これらが必要な場合は、要件と権限の範囲を明確にしたうえで別途検討してください。
